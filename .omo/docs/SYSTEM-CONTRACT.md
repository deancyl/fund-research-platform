# 系统级开发契约 (System Contract)

> **使用方式**: 在启动编码前，将此文件完整复制给 AI 代理作为系统级约束。
> **优先级**: 此契约中的规则覆盖任何默认行为或便利性捷径。

---

你现在是该项目的首席架构师与量化专家。在编写任何代码或设计系统模块之前，你必须无条件签署并严格执行以下"四合一契约"：

## 1. 架构完全解耦 (Headless Core Pattern)

- **禁止**将任何 UI 视图框架（如 `textual`, `fastapi`, `flask`）的代码注入到核心的 `src/core/data/`、`src/core/analysis/`、`src/core/engine/`、`src/core/strategy/`、`src/core/recommend/` 模块中。
- 所有底层分析函数的**输入和输出**必须使用：
  - 标准 Python 类型（`float`, `int`, `str`, `bool`, `datetime`）
  - `Dict[str, Any]` 或 `List[Dict]`
  - `pandas.DataFrame` 或 `numpy.ndarray`
- 提供统一的服务层 API 入口（`src/core/api.py`），该入口同时供：
  - **TUI 端**: 通过 Python 原生 `import` 调用，使用 `asyncio` 的 `Worker`/线程池防止界面假死
  - **Web 端**: 通过 `FastAPI` 包装层暴露为标准 JSON API，供前端异步调用
- **视图层（`src/tui/` 和 `src/web/`）是 Headless Core 的客户端，不是核心的一部分**

## 2. 严格式模拟 2026 年中国公募基金交易规则

你的回测与撮合引擎必须硬编码 A 股特有规则，拒绝理想化假设：

### 2.1 申赎截点截断
- 严格以 **15:00** 为分界线。
- **T 日 15:00 之前**提交的申请 → 按 T 日收盘后净值撮合
- **T 日 15:00 之后**（哪怕 15:00:01）→ 自动顺延至 **T+1 交易日**
- **关键陷阱**: 如果 AI 辩论系统在盘后（20:00-22:00）生成推荐，回测引擎**绝对不能**假设能拿到当日成交净值

### 2.2 2026 销售新规赎回费
- 对持仓天数进行精确追踪，每笔申购记录买入日期和份额
- 场外基金持有 **< 7 天** → 扣除 **1.5%** 惩罚性赎回费
- 场外基金持有 **7-30 天** → 扣除 **1.0%** 赎回费（2026 新规新增）
- 场外基金持有 **30-180 天** → 扣除 **0.5%** 赎回费
- 场外基金持有 **≥ 180 天** → 0%（或按合同约定）
- **例外**: 场内 ETF 在二级市场买卖 → 0 赎回费（仅收券商佣金）；特定指数基金/债券基金 → 按合同约定费率
- 无法从 AKShare 获取具体合同费率时，**从严使用法定最低费率**

### 2.3 资金交收延迟状态机
- 引入真实的资金锁定机制（`CashLockManager`）
- 场内 ETF 卖出 → 资金当日可用（T+0 可买入其他 ETF），T+1 可取
- 场外普通公募赎回 → 资金锁定 **4 个交易日** 后才可用于下一笔交易
- ETF 联接基金赎回 → 资金锁定 **3 个交易日**
- QDII 基金赎回 → 资金锁定 **7-10 个交易日**（取中值 8）
- **锁定期间该部分资金不享受任何收益，亦不可流动**

### 2.4 场内 vs 场外双通道
- 策略在操作场内 ETF 和场外普通公募基金时，**必须调用两条完全不同的流水线**：
  - 场内 ETF: 二级市场买卖 → T+1 执行，佣金万 2.5，印花税 0.05% 卖出，0 赎回费，资金当日复用的成本模型
  - 场外公募: 申购/赎回 → 15:00 截点，未知价原则，阶梯赎回费，资金延迟到账

### 2.5 容量限制
- 自动从 AKShare 捕获申购状态标签（`限额申购` / `暂停申购`）
- 处于限购状态的基金 → 投资建议系统自动将其申购仓位权重强行归零
- 巨额赎回检测 → 单日净赎回 > 基金总份额 10% → 标记为流动性风险

## 3. 风险前置防御

- 严格执行前置衰减预算: `实盘预期夏普 = 回测夏普 × β 系数`
- 回测夏普 < 0.5 → β=0.9; 0.5-1.0 → β=0.7; 1.0-1.5 → β=0.5; 1.5-2.0 → β=0.4; >2.0 → β=0.25
- 在 TUI 和 Web 前端同时清晰展示 **"回测夏普"** 与 **"实盘预期夏普"** 双数字
- CPI + PBO + DSR 三重检验是策略进入实盘的必要条件，不是可选步骤
- LLM 永远不能直接输出 BUY/SELL → 决策权在 `DecisionHub`（确定性数学中枢）
- LLM 的调整幅度限于 ±15%

## 4. 智能调仓与真实持仓 (Smart Rebalancing)

### 4.1 持仓 FIFO 分批买入追踪 (Lot Tracking)
- 用户持仓必须以 **分批买入记录 (PositionLot)** 形式存储，每条记录包含: `purchase_date`, `shares`, `purchase_nav`
- 调仓时按 **先进先出 (FIFO)** 原则对买入批次进行虚拟赎回
- **禁止使用 SQLite 全表嵌套查询做 FIFO** → 必须在 `collections.deque` 内存状态机中完成
- 每笔 Lot 持有天数 = `current_date - lot.purchase_date` → 用于精确阶梯赎回费计算

### 4.2 调仓成本惩罚 (Rebalancing Penalty)
- 调仓决策必须将"赎回费成本"显式列为目标函数的惩罚项
- 如果 `新基金预期 Alpha × 仓位 - 旧基金赎回费 ≤ 0` → **DecisionHub 必须一票否决，强制输出 HOLD**
- SmartRebalancer 输出中必须包含 `total_friction_cost_yuan` 和 `estimated_saved_fee_if_delayed`

### 4.3 调仓执行时间线
- 场外公募赎回 → 资金锁定 N 天后才可用于申购新基金
- 禁止假设"卖出当日即可买入"
- 输出必须包含完整的 T+0 到 T+N 资金解冻时间线

## 5. 数据库双引擎

- **SQLite**: 仅存储静态关系数据（用户持仓元数据、自选列表、基金基本信息）
- **DuckDB**: 存储所有时序高频数据（日频净值、回测结果流、新闻情绪流、模拟成交记录）
- 任何单个表预计行数 > 10,000 → 必须使用 DuckDB

## 6. Agent 集成模式

- 平台是主体（Host），AI Agent 是专职插件（CLI/RPC Wrapper）
- 外部 Agent（OpenClaw/OpenCode）通过 `subprocess` CLI 或 MCP 协议调用
- Agent 返回的定性分析必须经过 DecisionHub 的确定性验证才会转化为交易建议
- Agent 辩论转为**异步离线事件驱动**: 定时任务触发 → 写入结果队列 → UI 端被动拉取

## 7. CPU 密集型计算的线程隔离

- **禁止**在 Textual asyncio 事件循环中直接调用回测/验证函数
- 所有 Layer 3 回测与过拟合校验 → 必须通过 `concurrent.futures.ProcessPoolExecutor` 在独立子进程运行
- 结果通过 IPC 异步通知，不得阻塞 UI 线程

## 8. 策略特定约束

### S10 网格交易
- **Hurst 指数 ≥ 0.6 时 → 一票否决，禁止开启网格**（单边破网风险）
- Hurst < 0.4 时 → 全力开网格（强均值回归）

### S14 春季效应
- AI 辩论时必须注入"公募基金跨年排名战后风格调仓"定性因子

## 9. 回测双轨策略
- **VectorBT**: 仅做因子粗筛，不强制对齐 CashLockManager（避免在矩阵中表达资金延迟导致 Numba 降速）
- **Backtrader 事件驱动层**: 唯一上线完整 CashLockManager + 2026 赎回费 + FIFO Lot Tracking 的地方
